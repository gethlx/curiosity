# 好奇心 · Curiosity

**从一个说不清的疑问，找到值得理解的知识。**

好奇心是一个正在设计中的 AI 知识探索 Skill，面向约 14 岁、对世界充满好奇的孩子。孩子可以从观察到的现象、自己的猜测或模糊兴趣开始；AI 帮助辨认问题、发现相关概念、讲清它们的关系，再用通俗讲解、贴切类比和交互网页支持探索。

不必先知道专业术语，也不必先学会写提示词。

> **当前阶段：设计完成局部对齐，尚未实现。** 当前依据是 [V3 需求分析与设计方案](SKILL_DESIGN_V3.md)。仓库还没有可安装的 Skill、交互样板或真实模型效果评测；文中的体验与路线均为规划。

## 从什么问题开始

| 孩子可能这样问 | 好奇心希望帮助他做什么 |
|---|---|
| “船是钢做的，为什么不会沉？” | 从现象找到浮力、排水与平衡的关系，通过改变载货量观察条件与边界 |
| “给 AI 补一句背景，它就换了答案，是刚学会了吗？” | 区分观察、猜测和可能解释，找到适用概念 |
| “没有照片，怎么知道古人穿什么？” | 理解实物、记录与推断分别提供什么证据 |
| “这几个词我都认识，但不知道怎么联系。” | 理清概念的作用和关系，避免把所有知识排成先后步骤 |
| “太细了”“没懂”“有意思，继续” | 调整解释层级、换一种讲法，或由 AI 提出值得继续的问题 |

这些是设计场景，不是已完成的儿童使用测试。这里的“新知识”指对使用者而言的新认识，不等同于模型产生了经过验证的科学发现。

## 计划怎样工作

```text
观察、问题或模糊描述
  → 辨认求知意图，必要时用容易回答的问题澄清
  → 发现有解释价值的概念与关系
  → 按当前已知选择讲解深度
  → 通俗解释，结合适用的类比与交互探索
  → 补上理解缺口、提出下一问题，或停在这里
```

AI 承担专业概念的发现和后续提问，不把探索负担交回孩子。选项、类比和预测题按需要使用，允许直接解释、跳过或结束。已有概念不必重复讲，尚不确定的解释也不能为了连贯而补造。

首版规划包含**文字探索与交互网页**：主题明确、可靠模型能表达条件或过程时，在简短解释后默认制作并验证网页；尊重纯文字偏好，能力不足时明确降级。页面生成、实际运行和真实理解效果分别验证。

## 实现思路与范围

以一个 LLM、精简 Skill、按需读取的支持材料及宿主已有工具实现。查资料、生成文件与打开网页依赖宿主能力；不预建知识图数据库、多角色系统或跨会话用户档案。

- **Curio**：借鉴模拟初学者追问的设计，根据当前障碍选择澄清、深入或拓展。
- **Co-STORM**：借鉴从未覆盖的资料与关系中发现下一问题，优先补足原问题的缺口。
- **eli5 / show-me**：按需协作通俗讲解与最小有效视觉表达；好奇心自带页面规范，两者不是运行前提。

适用于日常科普、概念探索和跨领域兴趣。作业代答、考试复习、故障排查、专业咨询和代执行请求交回宿主正常流程；AI、网络等主题的知识探索仍在范围内。
