# 好奇心 · Curiosity

**从一个说不清的疑问，找到值得理解的知识。**

好奇心是一个 AI 知识探索 Skill，首版已经实现，并完成本地模型检查和随机画像探索；体验中发现的问题仍在修订范围内。用户可以从观察到的现象、自己的猜测或模糊兴趣开始；AI 帮助辨认问题、发现相关概念、讲清它们的关系，再用适合当前基础的解释、贴切类比和交互网页支持探索。

约 14 岁是默认表达起点和首版主要验证对象，不是固定档位或知识深度上限。其他年龄的初学者、有部分基础及专业用户的知识探索也在范围内；实际效果仍需验证。

不必先知道专业术语，也不必先学会写提示词。

## 从什么问题开始

| 你可以这样问 | 好奇心希望帮助你做什么 |
|---|---|
| “船是钢做的，为什么不会沉？” | 从现象找到浮力、排水与平衡的关系，通过改变载货量观察条件与边界 |
| “给 AI 补一句背景，它就换了答案，是刚学会了吗？” | 区分观察、猜测和可能解释，找到适用概念 |
| “没有照片，怎么知道古人穿什么？” | 理解实物、记录与推断分别提供什么证据 |
| “这几个词我都认识，但不知道怎么联系。” | 理清概念的作用和关系，避免把所有知识排成先后步骤 |
| “这些定义我知道，直接比较条件。” | 压缩已知内容，使用准确术语解释关系与边界 |
| “太细了”“没懂”“有意思，继续” | 调整解释层级、换一种讲法，或由 AI 提出值得继续的问题 |

这些场景用于设计和模型验收，尚未取得真实用户效果证据。这里的“新知识”指对使用者而言的新认识，不等同于模型产生了经过验证的科学发现。

## 计划怎样工作

```text
观察、问题或模糊描述
  → 辨认求知意图，必要时用容易回答的问题澄清
  → 发现有解释价值的概念与关系
  → 分别调整语言复杂度与当前话题的专业深度
  → 通俗解释，结合适用的类比与交互探索
  → 补上理解缺口、提出下一问题，或停在这里
```

AI 承担专业概念的发现和后续提问，不把探索负担交回用户。选项、类比和预测题按需要使用，允许直接解释、跳过或结束。已有概念不必重复讲，尚不确定的解释也不能为了连贯而补造。

**轻量适应是首版 MVP 的必需能力。** 默认首轮提供有用解释，准确术语按需补释义；用户明确偏好优先，已知判断限于当前话题，误判后在下一次回应调整。不先调查水平，不测整体词汇量，也不增加独立的用户评估流程。

首版规划包含**文字探索与交互网页**：主题明确、可靠模型能表达条件或过程，且操作能增加解释价值时，在简短解释后默认制作并验证网页；尊重纯文字偏好，能力不足时明确降级。页面生成、实际运行和真实理解效果分别验证。

## 实现思路与范围

以一个 LLM、精简 Skill、按需读取的支持材料及宿主已有工具实现。查资料、生成文件与打开网页依赖宿主能力；不预建知识图数据库、多角色系统或跨会话用户档案。

- **Curio**：借鉴模拟初学者追问的设计，根据当前障碍选择澄清、深入或拓展。
- **Co-STORM**：借鉴从未覆盖的资料与关系中发现下一问题，优先补足原问题的缺口。
- **eli5 / show-me**：按当前基础选择协作，页面和文字保持相同解释深度；不因调用呈现技能而重置到零基础。好奇心自带页面规范，两者不是运行前提。

好奇心专注于帮助用户理解知识：从日常现象中发现概念，弄清事物为什么这样、概念之间有什么联系，再沿着兴趣深入新的领域。初学者可以从模糊的疑问开始，已有基础的用户也可以直接探讨机制、证据和成立条件。

## 本地使用

在 Codex 中打开本仓库，可通过项目内技能入口加载 `$curiosity`，例如：

```text
用好奇心聊聊：给 AI 补一句背景后，它为什么会讲出新东西？
```

Skill 源文件位于 `curiosity/`，`.agents/skills/curiosity` 是指向它的项目内软链。两个 HTML 样板是独立文件，无需安装前端依赖；可使用本地 HTTP 服务预览。当前只验证了 Codex 本地主宿主。
